# 驻场 SOP

对内用。对外只讲官网首页那四步：先看、先斩一处、上线人不走、教会再走。档位和带人规则仍以 `工作室.md` 的三门九境为准，本篇不另立等级。

参考过《AI-FDE 驻场服务全流程作业指南白皮书》（大任智库，2026-08）的做法，按剑来自己的规模改成轻量版。不抄它的式名和表号，不对外引用它的数据。

## 总则

- 剑斩流程，不斩人。跟一线说话用请教的口气，他们比我们懂这摊活。
- 先看清再动手。看清之前不改东西、不给方案、不随口答应。
- 一次只斩一两处。做出一处看得见的，胜过铺开十处。
- 上线是开始用，不是做完。用起来是过程，指标动了才算做成：降本、增效，或新业务、原有服务能力的扩展，不一定是少用人。立项时先约定看哪几个指标。
- 留痕：说过的有纪要，定下的有确认，改范围的有记录。口头答应「顺手做掉」的，一律先记进待办，主理人点头再做。

## 第一步 · 先看

进场前（主理人带）：

- 读懂这家公司：做什么、谁拍板、现在用哪些系统和表。
- 认人，四类缺一不进场：
  - **拍板的**：对结果负责的老板或负责人，不是传话的
  - **一线骨干**：活最多、抱怨最多、最懂流程的人
  - **管系统的**：能调出数据、说清现有系统的人
  - **可能反对的**：现有系统的使用部门、原厂商
- 数据先摸底：哪些表、哪些系统、能不能导出、导出要不要审批。

进场头两周：

- 跟一线把一单从头走到尾，至少走三遍，里面要有一遍出过岔子的。
- 看表格、纸单、微信群里的补救。那才是真流程。
- 问事，不问观点：「上一次出问题是哪天、当时怎么处理的」，不问「你觉得 AI 能做什么」。
- 每天记卡（见下），两周不少于 15 张。

出口：把看到的卡在哪讲给拍板的人听，他认了，才往下走。

## 第二步 · 先斩一处

- 每张卡追三层：他说要什么 → 背后要解决什么 → 谁为什么在乎。
- 挑一两处：高频、真疼、数据够、两周能见到东西。
- 跟拍板的人写清楚「做成什么样算成」：现在是多少、要做到多少、怎么量。没有现在的数，先小样本量一次。
- 两周内给一线一个能用的半成品。每次给他们看，反馈当天记下、当天定怎么处理。
- 用真实的单测，不挑好看的样例。

出口：一线说「这个能用」，拍板的人签字认这一处。

## 第三步 · 上线人不走

- 上线头一个月按护航期过：人在现场，每天看一遍，出事当场接。
- 问题分三级：
  - **业务停了**：立刻处理，15 分钟内告诉主理人和客户拍板的人
  - **能绕过去**：当天解决
  - **体验问题**：本周清掉
- 每周给拍板的人一份短报：头条写第二步约定的那个数变了多少，再写问题、下周做什么、需要他们配合什么。
- 价值按第二步的口径算，数从客户自己的系统里取，不自说自话。

出口：连续稳定跑满约定的观察期，拍板的人确认这处值。

## 第四步 · 教会再走

- 客户那边挑一两个骨干带，不挑最闲的人。业务、管系统的各一个最好。
- 带四层：会用 → 会日常维护 → 会查常见问题 → 能自己改一处。
- 先我做他看，再他做我看，最后他做我抽查。
- 留下：操作说明、常见问题（上线以来出过的业务停了、能绕过去这两级问题都要有）、出事找谁。

离场前清点：

- [ ] 账号、权限、密钥交还，我们这边的账号注销
- [ ] 文档交齐，对方签收
- [ ] 没做完的事写明谁接、什么时候
- [ ] 后续找谁对接，告诉拍板的人
- [ ] 个人电脑里不留客户数据

离场后：

- 复盘三问：约定的数做到没有？成在哪、败在哪？哪些做法留下来，哪些以后别再做？第三问不许空。
- 能复用的东西（流程图、话术、清单、踩过的坑）脱敏后进 `knowledge/`；能对外讲的写成 `案例/` 一篇。
- 对照 `工作室.md` 的剑的四维，看这一趟谁该升境，附这一趟的实证。

## 卡片

### 现场卡（第一步，一事一卡）

| 栏 | 写什么 |
|---|---|
| 看到了什么 | 客观写操作、等待、返工、补录，不评价 |
| 原话 | 一线怎么说的，保留口语 |
| 多久一次 | 每天 / 每单 / 每周，写估算依据 |
| 影响 | 耗时、出错、背锅、钱 |
| 我猜的原因 | 标「猜」，没核实不写进结论 |

### 立项单（第二步，一处一张）

| 栏 | 写什么 |
|---|---|
| 要解决的事 | 用客户的话写，不写「上个大模型」这种手段 |
| 做成什么样算成 | 现在多少、做到多少、怎么量、数从哪来 |
| 做什么、不做什么 | 写清边界 |
| 依赖 | 要哪些数据、权限、系统接口 |
| 节点 | 半成品哪天、上线哪天 |
| 谁配合 | 客户那边谁、什么时候、配合什么 |

签字：客户拍板的人 + 主理人。签了以后改范围走记录。

## 红线

- 客户数据不进个人设备，不带出客户环境；要带出先拿书面同意。
- 案例对外只写行业，不写客户名、不写数字。
- 不越权承诺，不做合同外的私下交易，不掺和客户内部人事。
- 进度和问题如实说。客户能接受失败，不能接受瞒着。
