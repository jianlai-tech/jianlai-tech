## 一条案例必须有

1. 行业（对外标题用这个，不用客户名）和门类（两个字，官网书架按它筛；已有门类优先复用，别同义另起一个）
2. 进场时卡在哪
3. 做成了哪几段能跑的工序
4. 驻场怎么做的：人进去先做哪段、怎么边用边改（证明是驻场，不是远程外包）
5. 驻场眉批：现场踩过的坑，2–4 条，官网用朱笔批注排在书页天头。只写过程，禁止数字和客户名
6. 这套系统现在是谁在用（只写角色：老板 / 员工 / 老师 / 仓管，不写姓名）

## 一条案例禁止有

- 客户真名、内部品牌码、内部仓库名
- 营收、人数、单量、ROI、客户数
- 未授权实拍；示意必须标「示意」
- 把家教现场写成招生广告

## 讲案例放什么、界限在哪（2026-10-06 定）

一册整书按这个顺序：封面 → 目录 → 账页（投入与产出）→ 序一 生意 → 序二 驻场 → 按九式一式一章。

| 能写 | 写法 |
|------|------|
| 我们的投入 | **不写价格**（2026-10-06 主理人定：价格是报价锚点）。写周期到月、谁进场（道长 / 剑修）、每段做了什么、上线后怎么维护 |
| 我们的交付 | 做了哪些端、覆盖哪些部门、系统规模（表、接口这类我们自己的工程量，取整写「两百多」） |
| 速度与响应 | 只比人力和工期（同等范围常规外包几人几个月），口径写在同页；响应写我们的真实节奏（每天在群、当天回、多数当周上线） |
| 客户的生意 | 怎么赚钱、链路、卡在哪、怎么盘活，只讲结构不讲数 |
| 过程 | 驻场怎么做、踩过的坑（眉批） |
| 截图 | 现网截，先跑脱敏：数字清零、手机号打星、人名 ○○、品牌 ××、长备注糊、头像糊、侧栏裁 |

| 不能写 | 为什么 |
|--------|--------|
| 客户的营收、利润、单量、学员数、员工数、ROI、提效百分比 | 客户经营数据，未授权；提效比例没对照组，算不准 |
| 「帮客户多赚了 X」 | 没法归因到系统 |
| 客户名、品牌名、人名、地名到区县 | 能被认出来 |
| 合同细节、付款方式、项目价格、外包对照价 | 商务秘密；价格会变成报价锚点 |

页面上不写「已脱敏」「示意图」这类说明文字；脱敏靠截图本身做到，规则只留在本文件。

新现场先在本目录加一篇，再写入 `cases` 表。
